# Setup Manual: *How do LLMs Compute Verbal Confidence?* Reproduction

## Overview

This experiment investigates how large language models internally compute the "verbal
confidence" they report when asked to rate how likely their own answer is correct. It runs a
battery of forward-pass and activation-intervention analyses (steering, patching, noising,
swapping, probing, attention blocking) over Gemma 3 27B IT (primary), Qwen 2.5 7B Instruct, and
Magistral Small 24B, evaluated on TriviaQA, Big-Math, and MMLU. This manual sets up a single
machine — GPU access, Python environment, package versions, credentials, and a filesystem layout
— to the point where the reproduction pipeline can be started. It does not cover running the
experiments themselves; see [Next steps](#next-steps).

## Requirements

### Hardware

| Component | Spec called for | Notes |
|---|---|---|
| GPU | 1×H100 80GB or 2×A100 40GB (`device_map="auto"`) for Gemma 3 27B (~54GB bf16) and Magistral 24B (~48GB bf16); a single 40–48GB GPU is enough for Qwen 2.5 7B (~15GB bf16) | Reserve ≥20GB of headroom above the weight footprint for any run using `attn_implementation="eager"` (required for the attention-blocking experiment) — it materializes the full attention matrix and is much more memory-hungry than SDPA/FlashAttention. |
| RAM | No explicit floor; used to cache clean activations (float16) on CPU | Budget several GB per 3,000-trial activation-collection run (see Data setup). |
| Disk | No explicit floor; must hold model weights, datasets, and cached activations/results | |
| CPU | No explicit floor | |

### Credentials / gated access

- **Hugging Face token** (`HF_TOKEN` or `HUGGING_FACE_HUB_TOKEN`) with the Gemma 3 license accepted
  on the model page, for `google/gemma-3-27b-it`.
- **OpenAI API key** (`OPENAI_API_KEY`), for `gpt-4o-mini` grading and hedging checks.

### Verdict from the reproducibility assessment (machine `k-ai02`)

The assessed machine **partially satisfies** requirements — no hardware blockers, but two
provisioning gaps and several unverifiable items:

- **GPU mismatch, not a capacity problem.** The assessed machine has 8×NVIDIA RTX A6000 (48GB
  each) instead of an H100 or A100. Aggregate/pair memory (2×48GB) exceeds the 2×A100-40GB
  alternative, so a 27B model should shard successfully via `device_map`, but A6000 has lower
  memory bandwidth and no full NVLink mesh — real throughput versus the paper's H100/A100 baseline
  is unverified. If your machine has the named cards, this doesn't apply; if not, expect capacity
  to work but budget extra time for throughput.
- **No required Python packages installed** on the assessed system Python — all of `torch`,
  `transformers`, `scikit-learn`, `accelerate`, `datasets`, `numpy`, `scipy`, `pandas`,
  `matplotlib`, `openai`, `tqdm` were absent. This is exactly what [Environment setup](#environment-setup)
  below addresses.
- **Unverified, credential-gated:** Gemma 3 27B IT access and OpenAI API access — no tokens were
  set in the assessed shell. Obtain both before starting (see below).
- **Unverified, requires actually running the pipeline:** dataset integrity/dedup counts,
  the calibration gate (77.4% accuracy / 0.12 ECE / 0.71 AUROC on TriviaQA), and multi-GPU
  throughput/stability under sharding. These can only be confirmed once you run Experiment 0 (see
  [Next steps](#next-steps)).
- Python 3.10+, bf16 support, RAM, disk, and CPU were all satisfied on the assessed machine with
  large margin.

## Filesystem layout

No exact paths are named by the spec or guidebook, so this is a recommended layout. Reference
these paths consistently in every later step rather than introducing new ones.

```
$PROJECT_ROOT/
├── code/                     # cloned/placed reproduction pipeline code
├── data/
│   ├── raw/                  # downloaded datasets, one subdir per dataset
│   │   ├── triviaqa/
│   │   ├── bigmath/
│   │   └── mmlu/
│   └── partitions/           # the disjoint trial-pool partition (§2.3.4 of the guidebook),
│                              # recorded once and reused by every experiment
├── checkpoints/               # downloaded model weights (HF cache or explicit snapshot dir)
│   ├── gemma-3-27b-it/
│   ├── qwen2.5-7b-instruct/
│   └── magistral-small-2506/
├── activations/                # cached clean activations, per-position files, float16
├── results/
│   ├── grades/                # cached GPT-4o-mini correctness/hedging grades
│   ├── logs/                  # per-experiment run logs
│   └── figures/                # generated plots
└── .env                        # HF_TOKEN / HUGGING_FACE_HUB_TOKEN / OPENAI_API_KEY, not committed
```

Recommended environment variables (define in `.env` or your shell profile, all rooted at
`$PROJECT_ROOT`):

```
PROJECT_ROOT=/path/to/project
HF_HOME=$PROJECT_ROOT/checkpoints/.hf_cache
HF_TOKEN=<your Hugging Face token>
HUGGING_FACE_HUB_TOKEN=$HF_TOKEN
OPENAI_API_KEY=<your OpenAI API key>
HF_DATASETS_CACHE=$PROJECT_ROOT/data/raw/.hf_datasets_cache
```

Setting `HF_HOME` and `HF_DATASETS_CACHE` under `$PROJECT_ROOT` keeps all downloaded weights and
datasets inside the layout above rather than scattered in a user home directory, which matters
given the multi-tens-of-GB checkpoint sizes.

## Environment setup

1. Confirm Python 3.10+ is available: `python3 --version`.
2. Create `$PROJECT_ROOT` with the subdirectories from [Filesystem layout](#filesystem-layout):
   `mkdir -p $PROJECT_ROOT/{code,data/raw/{triviaqa,bigmath,mmlu},data/partitions,checkpoints,activations,results/{grades,logs,figures}}`.
3. Create and activate a virtual environment inside the project (e.g.
   `python3 -m venv $PROJECT_ROOT/.venv && source $PROJECT_ROOT/.venv/bin/activate`).
4. Install a CUDA-matched `torch` build (2.3+) per the official PyTorch instructions for your
   driver/CUDA version, then install the rest of the stack:
   `pip install "torch>=2.3" "transformers>=4.50" accelerate datasets "scikit-learn>=1.3" numpy scipy pandas matplotlib openai tqdm`.
5. Verify GPU visibility and bf16 support: `python3 -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0)); print(torch.cuda.is_bf16_supported())"`.
6. Set `HF_HOME`, `HF_TOKEN`/`HUGGING_FACE_HUB_TOKEN`, `HUGGING_FACE_HUB_TOKEN`, `OPENAI_API_KEY`,
   and `HF_DATASETS_CACHE` as environment variables (from `.env`, per the layout above).
7. Accept the Gemma 3 license on the Hugging Face model page for `google/gemma-3-27b-it`, then
   authenticate: `huggingface-cli login` (or rely on `HF_TOKEN` picked up automatically).
8. Clone or place the reproduction pipeline code at `$PROJECT_ROOT/code`.
9. Sanity-check API access: a minimal `openai` client call against `gpt-4o-mini`, and a minimal
   `transformers` load of a small public model, to confirm both credentials work before attempting
   the large Gemma 3 27B download.

## Data setup

The guidebook names three datasets, all obtained via the Hugging Face `datasets` hub — no manual
download or licensing steps beyond standard HF access are described:

- **TriviaQA** (primary): the `rc.nocontext` / unfiltered configuration, **validation split**.
  Deduplicate on normalized question text before sampling. Store the raw download under
  `$PROJECT_ROOT/data/raw/triviaqa`.
- **Big-Math** (generalization): available on the Hugging Face hub. Store under
  `$PROJECT_ROOT/data/raw/bigmath`.
- **MMLU** (generalization): available on the Hugging Face hub, multiple-choice format. Store
  under `$PROJECT_ROOT/data/raw/mmlu`.

Once downloaded, partition the deduplicated TriviaQA pool **once, up front**, into the disjoint
sets the guidebook's experiments read from (activation-collection set, calibration set, and the
per-experiment test sets) and record that partition under `$PROJECT_ROOT/data/partitions` — every
later experiment must reuse the same partition rather than resampling.

Model checkpoints (`google/gemma-3-27b-it`, `Qwen/Qwen2.5-7B-Instruct`,
`mistralai/Magistral-Small-2506`) download automatically on first `transformers` load into
`$HF_HOME` (i.e. `$PROJECT_ROOT/checkpoints/.hf_cache`) once credentials are set up — no separate
manual step beyond ensuring `HF_HOME` points there before the first run.

## Verification

Before attempting any experiment, confirm:

- [ ] `python3 -c "import torch, transformers, accelerate, datasets, sklearn, numpy, scipy, pandas, matplotlib, openai, tqdm"` runs with no import errors, inside the project virtualenv.
- [ ] `torch.cuda.is_available()` is `True` and `torch.cuda.get_device_name(0)` reports the expected GPU(s); `torch.cuda.is_bf16_supported()` is `True`.
- [ ] `nvidia-smi` shows enough free GPU memory (≥54GB reachable via sharding for Gemma 3 27B, plus ≥20GB headroom for any eager-attention run) across however many GPUs `device_map="auto"` will use.
- [ ] `echo $HF_TOKEN` / `echo $HUGGING_FACE_HUB_TOKEN` are non-empty, and a `huggingface-cli whoami` succeeds.
- [ ] A test load of `google/gemma-3-27b-it` via `transformers` (even just `AutoConfig.from_pretrained`) succeeds without a gated-access error — confirms license acceptance took effect.
- [ ] `echo $OPENAI_API_KEY` is non-empty, and a minimal `openai` chat completion call against `gpt-4o-mini` returns successfully.
- [ ] The filesystem layout exists (`code/`, `data/raw/{triviaqa,bigmath,mmlu}`, `data/partitions/`, `checkpoints/`, `activations/`, `results/{grades,logs,figures}`), and `$HF_HOME`/`$HF_DATASETS_CACHE` point inside it.
- [ ] TriviaQA downloads successfully via `datasets.load_dataset` into `$HF_DATASETS_CACHE`, and a deduplicated question count in the expected range (~11k unique after dedup) is obtained.

## Next steps

Once the checklist above passes, proceed to the full reproduction guidebook
(`thesis.experiment.docs.manual`, `reproduction-guidebook.md`) for the actual experiment
sequence. Start with its §2 (shared setup — prompts, token positions, hook infrastructure) and
run **Experiment 0** (behavioral baseline and calibration) first: it is a hard gate — do not
proceed to any intervention experiment (steering, patching, noising, swap, probing, attention
blocking, generalization) until Experiment 0 replicates the target calibration numbers (77.4%
accuracy, 0.12 ECE, 0.71 AUROC on TriviaQA with Gemma 3 27B). The guidebook's §15 gives a
suggested execution order and a rough forward-pass compute budget for planning GPU time beyond
this setup.
