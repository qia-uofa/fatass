## User

## Agent
Read through `vconf/prompts.py`, `config.py`, `metrics.py`, and `grading.py` to answer concretely rather than in the abstract. Found the architecture is split cleanly: the class list/ranges/cue-text/steering-poles in `prompts.py` are consumed generically downstream (as "the K target tokens") by `metrics.py`, `positions.py`, `models.py`, and the steering/patching/noising experiments — so swapping the scale's vocabulary is mostly mechanical. Concluded: renaming the scale is easy; the calibration experiments don't have an obvious analog without inventing a new ground-truth grader.

## User
are you saying the reason "confidence" is meaningful only because it there is a ground truth behind confidence (correctness)?

## Agent
Corrected/sharpened the prior framing: the codebase studies confidence at two independent levels with different ground-truth dependence. (1) Mechanistic level (steering/patching/noising/probing — does the model have a causally-manipulable internal representation of the class it's about to verbalize) needs zero ground truth and transfers to any verbalized scale. (2) Validity/calibration level (does the verbalized class track reality) is where ground truth is load-bearing, because "is this signal real" is undefined without something external to check it against. Conclusion: confidence isn't meaningful *only* because of ground truth, but the paper's specific calibration claim only exists because correctness supplies one.
